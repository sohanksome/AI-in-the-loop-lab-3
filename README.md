# AI-in-the-loop-lab-3


## Part 2 — Draft AI Usage Guidelines

1. Section 1 — What AI tools we plan to use, and what we will use each for
   - We will use **Claude Opus 5** to write code for independent features — not for interactions between different systems. A human reviews all of this code before it is merged.
    - We will use **GitHub Copilot's** inline autocomplete while typing — not to write PR descriptions or DECISIONS.md entries.
    - We will use **Claude Sonnet 5** to create the skeleton/structure of new systems — a human first decides the architecture and requirements, and always adds features and adjusts behavior to fit our needs.
    - We will use **Claude Sonnet 5** to draft the first pass of docstrings and API documentation — a human always reviews and edits it before it is merged.
    - We will use **Claude Sonnet 5** to provide test cases — a human always runs the tests at least once and make sure the tests cover all edge-cases.
    - We will use **GitHub Copilot** to review pull requests — its comments are suggestions only, and the author decides whether to act on them. Every PR still needs at least one human approval (other than the author) before it can be merged.

2. Section 2 — How we will document AI interactions
    - For AI-generated code, we modify as little as possible and state in the commit message that it was generated by AI. Any later adjustments or fixes go in separate commits.
    - For test cases, we use code comments to mark whether each case was written by a human or by AI.
    - For PR descriptions, we clearly mark any part that was drafted or summarized by AI, such as the summary of changes..

3. Section 3 — How we will handle disagreements about AI output quality
    - If two ore more engineers disagree about whether AI-generated code is good enough to merge, the code steward has final say — not whoever wrote the prompt, and not whoever has more experience.
